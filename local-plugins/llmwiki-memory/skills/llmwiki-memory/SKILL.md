# LLM Wiki 长期记忆

这是 BugleCat 的默认会话生命周期 Skill，不等待用户点名。每个新会话在处理首个业务请求前加载一次；同一会话后续轮次沿用已召回内容，不重复灌入完整画像。

只使用 MCP 工具 `llmwiki(action=...)`，不要直接读写 `D:\LLMWIKI\wiki\user` 或 SQLite 数据库。`D:\llm-wiki-template` 是协议和初始化模板，只在用户要求修复、升级或创建 Wiki 时使用；实际记忆数据以 `D:\LLMWIKI` 为准。

## 读取

0. MCP 存活期间周期性增量采集 BugleCat 等客户端的新会话；当前会话写盘后最迟约一分钟进入 L0，不要求新建会话或手工导入，也不要在聊天主流程里同步运行采集脚本。
1. 每个新会话必须调用 `llmwiki(action="recall_user")`，再处理首个业务请求。召回失败时继续当前任务并简短说明，不得卡住会话。
2. 进入已有项目时，先调用 `llmwiki(action="project_status")` 确认 slug，再调用 `llmwiki(action="recall_project", project="slug")`。
3. 只有需要历史细节时才传 `query` 或 `sections`，不要一次加载所有分片。

## 写入边界

- 项目已确认决策、进度、待办和证据用 `record_project`，并附真实来源文件、测试命令或用户确认。
- 项目不存在时，只有用户明确要求建立长期项目记忆才调用 `initialize_project`。
- 密码、Token、Cookie、Secret、数据库口令和敏感业务正文不得写入。仓库契约、代码与测试始终是事实源。
- 用户画像候选必须有用户原话、至少 3 次独立出现且跨 2 个会话；`approve` 只能在用户明确批准后调用。

## 自动生命周期

- 会话开始：自动召回用户画像；已知项目同时召回项目短快照。
- 会话进行中：MCP 后台自动采集 L0，Agent 不阻塞、不显示黑色命令窗口、不把采集日志塞进对话。
- 项目任务完成或形成明确交接事实：用 `record_project` 记录短摘要和真实来源；不记录流水账。
- 返回“待蒸馏”时：从 `corpus` 提取满足阈值的候选并用 `propose` 提交。候选只进入待批准区；用户明确同意后才 `approve`。
- 当前会话的新内容进入 L0 后，可在同一会话后续轮次参与语料检索；它不会未经批准直接改变 L2 用户画像。

## 完成检查

写入后用 `recall_project` 复核可召回内容，确保状态真实、来源存在且不含敏感值。MCP 不可用时明确报错，不要静默改为直接写文件。
