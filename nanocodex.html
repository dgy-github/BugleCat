01这个项目到底是什么

BugleCat 是一个本地运行、可切换模型商并采用可插拔 Harness 的 coding agent，用来验证“一个模型怎样在受控环境里持续读代码、改文件、跑命令、看结果、再修正”。

它对齐的是 Codex / Claude Code 类工具的工程能力，而不是外观：交互式编码循环、17 个内置工具协议、仓库读写与结构化搜索、命令执行与后台 PTY、审批/沙箱、宿主级声明核验、会话恢复与文件检查点、AGENTS.md、Skills、MCP、上下文编辑和成本统计。

后端原生支持 OpenAI 兼容 /v1/chat/completions 与 Anthropic Messages /v1/messages，既可以接 DeepSeek、Claude、OpenAI、智谱、百炼、MiniMax 等托管 API，也可以把 base_url 指到本地 Ollama、vLLM、llama-server、LM Studio 或企业内网模型服务。

不是聊天壳

模型不能直接碰文件系统。它必须输出结构化 tool call，由工具层在沙箱/审批与宿主核验边界内执行，再把真实结果喂回模型形成闭环。

不是官方克隆

不宣称复刻官方云端容器、PR 自动 review 或内核级强隔离；它聚焦本地 coding agent 的核心可运行链路与可审计控制面。

适合放 GitHub 的点

它展示的是 agent 工程化：协议、权限、工具恢复、上下文编辑、宿主物理事实核验、多厂商兼容性和零 API 离线回归门禁。

03核心循环怎么跑

ncx-core::AgentLoop（以及 Python AgentLoop.run_turn()）驱动单个用户回合直到完成。一个回合内可能发生多轮模型调用；每轮可产生工具调用，经沙箱/审批/Hooks 与工具恢复策略处理后，工具结果再进入下一轮上下文，token 用量逐轮累计。

用户输入 → 调用模型 → 解析工具调用 → 沙箱/审批/Hooks → 执行工具与恢复 ↺ 核验与回合完成 
// rust/crates/ncx-core — 回合产物与统计快照
pub struct TurnOutcome {
    pub final_text: String,
    pub iterations: usize,          // 本回合循环了几轮
    pub stop_reason: StopReason,    // 完成 / 预算触顶 / 用户取消
    pub tools_used: Vec<String>,
    pub usage: TokenUsage,          // 含 prompt_cache_hit / miss 拆分
}
1. 组装上下文system prompt、AGENTS.md、memory、skills 描述、MCP schema、上下文裁剪策略和历史消息一起进入模型。
2. 调用模型OpenAI 兼容或 Anthropic Messages provider 发起请求；支持流式思考、正文和分片 tool_calls 聚合。
3. 工具派发ToolRegistry 按名称路由到 17 个内置工具或 MCP 工具；连续只读工具批次可并发执行。
4. 权限与 Hooks沙箱策略校验工作区与路径重解析点；审批策略与 PreToolUse / PostToolUse hooks 决定放行、拦截或请求用户确认。
5. 结果回填与恢复工具输出回到模型上下文；若遇到半截补丁或参数格式错误，ToolRecoveryPolicy 注入结构化修复提示。
6. 核验与持久化可选宿主级声明核验拦截“未测宣称已测”；最终答案、工具轨迹、检查点、token usage 和会话快照写入本地。

04针对 DeepSeek 与多模型网关做了哪些适配

OpenAI 兼容或 Anthropic 接口能跑起来只是第一步。真正做 coding agent 时，reasoner 思考回放、流式 tool call 分片、首包超时、HTTP 异常脱敏和 cache 计费都会踩坑。BugleCat 在 Provider 与 Harness 边界统一处理这些兼容问题。

优化点为什么需要实现位置
reasoning_content 回放DeepSeek reasoner 在 assistant 历史里有 tool_calls 但缺 reasoning 时可能拒绝后续请求；BugleCat 会为历史回合保留或补齐占位。ncx-provider / _sanitize_reasoning_replay()
reasoning 字段兼容不同兼容网关可能返回 reasoning_content、reasoning 或 Anthropic thinking block；统一抽取后 CLI/GUI 可把思考流和正文流分开显示。ncx-provider / _extract_reasoning()
DeepSeek thinking 参数映射off 映射到 thinking: disabled，max/high 映射到 DeepSeek thinking-mode 的扩展字段，避免配置写了但请求没带。ncx-provider / _apply_reasoning_effort()
自适应推理档auto 不再只是 no-op；遇到“报错/调试/debug/エラー”走 max，搜索类任务走 low，普通开发默认 high。ncx-core::auto_reasoning / agent/auto_reasoning.py

05工程取舍与边界

  • 核心循环清晰：ncx-core 统一管理会话、上下文编辑、预算、检查点与声明核验，CLI 与 Tauri GUI 共享同一套 AgentRuntimeProfile 与 70 个强类型协议方法。
  • 工具协议显式：17 个内置工具均有严格 JSON schema、参数校验和统一返回格式；模型不能绕过工具层直接写文件或跑命令。
  • 多模型商中立：内置 DeepSeek、Anthropic、OpenAI、智谱、百炼、MiniMax、Kimi、硅基流动与本地网关预设，一键切换无需重写工具层。
  • 安全不吹大：Windows 侧是策略级沙箱 + 工作区路径重解析点拦截，不宣称内核隔离；MCP 子进程运行在沙箱外且默认遵循 fail-closed 审批门禁。
  • 上下文可治理：结合 deterministic 压缩、opt-in 模型摘要以及旧工具输出/思考块定向裁剪，控制长会话成本与延迟。
  • 宿主级诚实核验：提供 ncx-core::verification 确定性声明核验器（host-rules-v3.4），可物理拦截“未运行测试却宣称通过”的幻觉声明。
  • 离线确定性回归：Rust 工作区、Tauri 宿主、Golden 评测门禁与 Python 测试全套可在无真实 API Key、无外网条件下 100% 确定性通过。
  • 没有覆盖的能力：尚未实现官方 Codex 的云端托管容器、GitHub PR 自动 review、完整 Computer Use 和 OS 内核级强沙箱。
一句话价值：BugleCat 证明的是“多个模型商可以接进同一套可审计的 Codex-style coding agent 工具链”，而且这套链路有权限边界、文件检查点、上下文治理、宿主事实核验和全套离线回归测试。
