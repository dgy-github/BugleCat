🎖 campaign 多 Agent 编排 · 流程图详解

不是更多 Agent，而是更好的指挥系统。核心：事件溯源(状态由回放派生) + 确定性编排(DAG) + 全链路治理(PolicyGate) + 抗毁(熔断/减员) + A2A 可换传输。按真实代码逐块画流程，每图配面试要点。

① 事件溯源② run 编排③ 单任务链④ PolicyGate⑤ A2A 传输⑥ 韧性/减员

① 事件溯源 + derive_state（状态由回放派生，无可变共享态）

面试要点
  • 状态永远由回放派生：derive_state(events, run_id) 纯折叠，不存可变共享态——取代黑板架构。
  • run_id 隔离多运行不混流；truncate_after(seq) 是真回滚/分叉。
  • 白得 durable resume：换进程/设备读同一事件库 replay 即恢复。事件总线队列满时 dropped_events 计数不静默丢。

② run() 编排主链路（DAG 拓扑分层 + 并发）

面试要点
  • DAG 拓扑分层调度：topological_layers 按 depends_on 分层；层内 Semaphore 限流并发，依赖未完的 task.skipped。
  • 裁判/运动员分离：Coordinator 只拆解+调度，Reviewer 独立验收（在单任务链里）。
  • 全程事件落 run_id 隔离的 EventLog，可 replay。

③ _execute_one_task 单任务链（制动→审批→治理→执行→验收）

面试要点
  • 写操作前多道闸：协同制动 → HITL 审批 → 选 agent(跳熔断) → PolicyGate → 超时执行 → 独立验收。
  • 治理用真实信号驱动：按 tier 估价入账、执行后按真实 token 再过 gate（否则 cost 恒 0 = 形同虚设）。
  • 失败联动：_after_failure → 熔断计数 + 降 health（喂给减员评估）。

④ PolicyGate 全链路治理（Policy-as-Code + 并发安全）

面试要点
  • Policy-as-Code 四规则：预算 / 数据出域 / 越权 / 注入扫描；对所有角色一视同仁（Coordinator 自己也受约束）。
  • 并发安全：asyncio.Lock 序列化预算读改写——asyncio 单线程也有跨 await 竞态。
  • 全链路 vet：Runtime 每任务 + LLMClient 每次调用共享同一闸；违规写 governance.violation 独立上报。

⑤ A2A 协议 + 可换传输（依赖倒置 · 幂等是重试前提）

面试要点
  • 依赖倒置：编排只依赖 Transport 抽象，换 InProcess ↔ HTTP/JSON-RPC ↔ SSE 实现即 单机→分布式，不动编排。
  • 幂等是重试的前提：HTTP 加重试+退避后必须配 message_id 幂等去重，否则 worker 重复执行/重复扣预算。
  • 信任边界：发送方 allowlist 防伪 + untrusted 标记 + 注入扫描——外部内容一律当数据不当指令。

⑥ 抗毁性：熔断 + 协同制动 + 三级减员 + 混沌演练

面试要点
  • 两层抗毁：单点熔断(≥3 失败,cooldown 自愈) + 链路协同制动(brake.signal 背压防雪崩)。
  • 三级减员：按 health 真实驱动评级 → 替补 / 降级(checkpoint+弱模型+Reviewer 加严) / 战时动员(+human 升级)；执行可降级、把关不降级、高难宁冻结。
  • 混沌演练：随机杀 agent 验证制动/补位——把上线准备度变成可衡量门禁，不靠感觉。
诚实边界（面试判断力加分）
  • 分布式是可运行 MVP（HTTP + 共享 SQLite + remote proxy）；生产级一致性仍需共享预算/health/breaker/leader——没有就不假装做，写进 SCALING.md。
  • 长期知识默认词法 TF-IDF，非神经 embedding（留 adapter 缝）。
  • 制动状态在内存维护（不每次全量 replay，避免 O(N) 随日志无界增长）。
