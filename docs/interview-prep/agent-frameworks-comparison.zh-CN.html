🔎 细节下沉（点开某维度看四家全文）

主循环 / 终止条件
nanocodex：run_turn 有界循环(组装→调模型→执行工具→喂回→循环);双预算(model/tool)+ backfill 历史合法性;5 退出点(无工具/error/cancel/预算/max)。
codex：agent loop——nanocodex 的循环就是从它移植的(同源)。
claude-code：turn 循环,用户可随时打断/插话(steering)。
pi：agentLoop/runLoop;steering + followUp;turn 之间可热换模型(见"模型切换")。
短期 / 会话记忆
nanocodex：messages 历史 + 结构化 State(任务状态)。
codex：会话历史(同源)。
claude-code：会话上下文自动管理。
pi：AgentMessage 与 LLM Message 分层(convertToLlm 转换)——这是 pi 的一个特色边界。
会话压缩
nanocodex：非破坏(for_model_edited 发送视图,原始不动);两趟=旧 tool 结果字符截断+user 边界丢最旧前缀;切点绝不落 tool_result。(LLM 摘要是优化方向,当前是截断)
codex：截断式压缩 ⚠️ 具体机制待核。
claude-code：分层缓存驱逐(不是"满了就摘要",是 cache eviction,越往后越贵越有损)：① microcompaction(最便宜·不调模型)——大 tool 结果(Read/Bash/Grep/Web…)offload 到磁盘,只留路径引用(热尾 inline / 冷存储可回读);含 cache-aware 变体(用 API cache editing 删旧结果不破坏 prefix)。② auto-compact(≈167K/200K 触发,reserve 20K,连续 3 次熔断)——spawn LLM 后台出结构化摘要(意图/文件+代码/错误+修复/反馈/待办/当前态)。③ session-memory compact(用预抽取 notes 跳过摘要调用)。+ rehydration(重读最近 5 文件≤50K + todos + 续跑指令)。核心:机械可回读压缩在前、LLM 有损摘要在后。
pi：compact() + reserveTokens(压缩时预留 token 余量)——本会话拆过。
长期记忆
nanocodex：项目记忆,"线索非事实"(recall 注入标 header;remember 仅 CONFIRMED+去重;consolidate 0.85)。
codex：靠 AGENTS.md 项目指令 ⚠️ 无独立长期记忆层?待核。
claude-code：CLAUDE.md + 记忆文件(跨会话持久)。
pi：核心不做,交 packages/扩展。
工具处理
nanocodex：shell/apply_patch;工具可见上限 9;apply_patch 工具描述逐字移植 codex。
codex：shell/apply_patch(nanocodex 源)。
claude-code：丰富工具集(Bash/Edit/Read/Grep/Task/…)。
pi：工具执行支持并行/串行(本会话拆过 tool execution)。
