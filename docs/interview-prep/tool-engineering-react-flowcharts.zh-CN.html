🎯 题眼

贯穿三不变量
  • 分类权不给模型：read_only()/危险与否是代码静态声明+保守白名单，不信模型自述。
  • 中途退出必 backfill 保历史合法：否则 OpenAI 协议下一次请求 400。
  • 语法合法≠语义正确：JSON mode 保证能 parse，不保证符合 schema，都要挂确定性断言+有界重试。
一句话：收窄副作用 + 结构化可校验 + 带明确终止/重试边界的循环——绝不让 agent 无界打转，也绝不把"没验过"伪装成成功。

🔁 一次工具调用的完整决策流

面试要点
  • 分类权不给模型：read_only() 是工具作者的静态声明，agent_loop 只信声明不信模型自述——一次幻觉就能导致并发写踩踏或跳审批。
  • 三处"⚠"是最容易被追问的坑：ok()=exit0 只判进程层成功不判语义正确；反馈回灌没熔断会让模型对同一噪声反复打转；渐进暴露纯词法打分可能漏召回。
  • backfill 是协议层可靠性：OpenAI 兼容协议下，assistant 的每个 tool_call 必须有配对 role:tool 应答，否则下次请求 400——不删消息（可能含有价值 reasoning）而是补占位。

⚖️ ReAct vs Plan-and-Execute 选型

维度ReAct（边想边做）Plan-and-Execute（先规划再施工）
结构reason+act 交替的有界单循环规划节点(无工具)+执行节点分离的多节点 pipeline
适合路径不确定、读多写少、要自适应(coding 主循环)写副作用、要人审、步骤明确(排产四段治理)
失败恢复隐式便宜：错误当 isError 喂回自纠显式集中：独立 verify 节点判 PASS/FAIL
可控性自适应但难审(报错随时改道)清单可审、可 dry-run、可并行、可分层(贵模型plan+便宜模型worker)
nanocodex 落点agent_loop.rs run_turn_innerorchestrator.rs：classify判high才切真Plan，PLAN_SYS写死"You have NO tools"防越权
口诀：不确定就 ReAct(自适应)，要可控就 Plan(可审可并行可分层)。update_plan 不算真 Plan——它是 ReAct 里的软清单(advisory，只给 UI 展示不改控制流)，真 Plan 必须有独立于规划的执行节点。
