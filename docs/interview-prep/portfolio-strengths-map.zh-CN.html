🦀 nanocodex

角色：LLM=执行者（沙箱托底）
最怕：假阳性（乱改文件/删库）
承重：权限双门 + 离线演化即边界

🏭 排产

角色：LLM=翻译官（LLM-as-interface）
最怕：假阳性（幻觉方案落地）
承重：确定性 workflow + 四段治理 + 评测飞轮

🔐 网关

角色：LLM=本地优先（local-first）
最怕：数据外泄
承重：脱敏 + 命中密钥硬 block

🎖 campaign

角色：LLM=被编排者（多 agent）
最怕：状态不一致 / 雪崩
承重：事件溯源 + 编排/A2A + 治理
30 秒开场话术：「我用同一套驾驭工程打了 4 个不同承重的实体——编码押权限（沙箱+审批+能力剥夺）、排产押确定性治理（workflow+四段治理+评测飞轮）、网关押隐私（脱敏+硬 block+local-first）、多 agent 押事件源编排。骨架相同：LLM 原始输出不直接落地、安全建在代码上、有确定性判据就不用 LLM judge、数据不出域。承重随业务变，方法论不变。」
