🔐 流程图 1 · 一次写操作的权限判定（v2 核心）

面试要点
  • 两道正交纯函数：SandboxPolicy.can_write 判物理（3 档模式 + 词法路径包含）⊥ Approver::classify 判越界（4 档 → 3 态）。
  • SessionGrants 短路：本会话精确命中过的命令直接 AutoApprove；一字不差匹配，fork/resume 即清空。
  • 三态出口：AutoApprove 直跑 / Ask 弹 ApprovalHandler（Deny·Once·Always）/ AutoDeny 拒（never 档报错）。
  • PolicyExecutor 只做容器（Job Object+timeout），决策在它之前已定死——判断与执行彻底分开。
  • 一句话：安全边界建在代码上不建在措辞上；danger 全开也不改 approval 策略，故 untrusted 未知命令仍会问。

🛡 流程图 2 · untrusted 三重过滤 is_trusted()（越界门内部）

这是「② 越界门」在 untrusted 档下的子流程：决定一条命令能不能自动放行。最危险的检查放第一步。

面试要点（务必背准顺序与数字）
  • 三步顺序：① 7 条 dangerous 正则扫全串（任意位置命中即 false）→ ② 剥路径/.exe、取 first_token 查 29 条白名单 → ③ base==git 再查 15 条写子命令。
  • 为什么正则放第一步：fail-safe——rm -rf 即便前面有可信 token 引导、或 rm 不在白名单，也先被拦。
  • 结合 escalation：untrusted 分支 = is_trusted(cmd) && !越界 ? AutoApprove : Ask；白名单是保守的——git status 自动、git push 仍问。
  • 它是「越界门 classify」的 untrusted 档内部逻辑，不是独立系统。

⚙️ 流程图 3 · 一个回合 run_turn（v1 Harness）

面试要点
  • 循环上限：for iteration in 0..max_model_calls（= max_iterations 与 task_budget 取小）；每步先查 cancel + 工具预算，为 0 则回填未应答 tool_call 再退出。
  • 工具视图每回合重建：schemas_for_query——≤9 全暴露，否则 ALWAYS_VISIBLE + 上回合 tool_hints + catalog_score 词法打分（上限 9），再叠 genome 覆盖。
  • 并发规则：当前+下一个都 read_only 才 join_all 并发；写/未知一律串行。
  • 历史合法性不变式：cancel/预算耗尽时 backfill_unanswered_tool_calls 合成占位回复——否则下次请求 400。

🗜 流程图 4 · 上下文压缩 for_model_edited（v3，非破坏发送视图）

面试要点
  • 两趟：① 压旧 tool 结果到 max_tool_result_chars → ② 仍超 max_chars 则在 user 边界丢最旧前缀。
  • 非破坏：self.messages 原始历史不动，压缩是「发送时视图」——保留原始才敢激进压（resume/回放/换模型）。
  • 硬规则：切点绝不落在 tool_result；前缀丢弃把切点推进到 user 边界并跳过打头孤立 tool——维护 OpenAI 历史合法性（否则 400）。
  • 换业务：编码留最近代码 diff；客服/售后留用户原始诉求+订单号（不同的保留优先级）。

🌳 流程图 5 · 编排 best-of-N（v5，父子无总线）

面试要点
  • 三通道通讯（无总线）：① prompt 下发（状态按值序列化进全新无状态子会话）② 文件隔离-提升（真 IPC）③ PASS/FAIL/BEST 裁决回灌。
  • 能力剥夺：classify/plan/verify 走 reason() = 空 ToolRegistry，代码级物理拿不到工具。
  • 隔离修的真实 bug：并行 apply_patch Add 同名文件撞车 → 每 worker 私有 ncx_worker_{pid}_{n} 拷贝；真 workspace 只在 verify 后被 promote 写一次。
  • 裁决健壮性：verdict_passed = !contains("FAIL")（位置无关）；BEST: 缺失/畸形兜底 index 0——偏向「往前推进」而非卡死。
  • 递归串行：子任务用 for 循环，每个先 promote 再进下一个（依赖可叠加）；并行会重新引入撞车。

🧬 流程图 6 · ncx-forge 离线演化循环（v6）

面试要点
  • 只演化文字：genome = system_prompt + 工具描述（纯文本），绝不动行为/权限。
  • 唯一接缝 + 可证明 no-op：NCX_GENOME 是训练↔运行唯一通道；空/错 → 字节级回退默认脚手架。
  • 训练接缝即安全边界：执行始终过沙箱 → 被不可信失败轨迹喂养的 teacher 也无法注入新能力。
  • sentinel 门：无法证明注入生效前拒绝训练——防「离线全绿是假象」。

⭐ 相对 codex 的三点再设计（面试主攻）

1 · 两层正交纯函数
  • sandbox/approval 拆成 can_write ⊥ classify
  • 每次重算、无持久跳转
  • 可单测、可回放
2 · 三层解耦
  • policy / approval / prompt 三层
  • ApprovalHandler 踢出 sandbox crate
  • 层间独立判定
3 · 能力剥夺 + 训练即边界
  • reason() 空 registry → 物理无工具
  • genome 只换文字、执行永过沙箱
  • 离线训练改不动安全边界

🎤 面试话术（90 秒）

「nanocodex 是我把 codex 用 Rust 重写的 agent。能原样搬的逐字搬——apply_patch 描述、@path、tool_calls 形态、沙箱三模式、审批四档。但权限控制我做了再设计：拆成两层正交纯函数——can_write 判物理、classify 判越界——再加一层人类提示，三层解耦、每次重算、只留一个窄的 session 授权。更进一步，用代码级能力剥夺（推理节点空工具）和训练接缝即安全边界（离线只演化文字、执行永过沙箱）把权限焊死。一句话：codex 给了我词汇，我把它做成了可单测、可回放、改不动安全边界的纯函数系统。」
