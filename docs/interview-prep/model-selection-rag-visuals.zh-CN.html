📚 RAG 优化分层塔

自上而下：先判该不该查，再逐层加优化，grounding 校验做在模型外。不是都要上——Agentic/Graph 只在特定场景才值得。

L0 基础
解决：用外部知识替代硬记/瞎编，答案可引用溯源。技术：chunk(按 markdown 标题切)+bge-small-zh+Qdrant top_k=3+citations。何时：知识静态、单跳可覆盖(规则/SOP/FAQ)。
L1 Query
解决：检索前决定要不要查/查哪个库/用什么 query(不是重写提示词)。技术：Routing(structured_sql vs rag，最大杠杆)+Rewriting+Expansion+HyDE+子问题分解。何时：同时有结构化源和非结构化源就必须 routing。
L2 检索
解决：最大化 top-k 相关度与信噪比(真正胜负手)。技术：Hybrid(BM25+dense，RRF 融合)+按业务单元 chunking+父子块+metadata pre-filter+rerank+file fallback。何时：query 里既有硬 token(编号)又有软表达。
L3 重排+据
解决：召回≠可用，精排+拼装+强制每字段回溯证据，检索侧掐死幻觉。技术：cross-encoder/LLM rerank(auto 降级)+top_k=3 最相关放首尾+citation-or-silence+回库 fuzzy 核验。何时：高准确/可审计/错答代价高。
L4 Agentic
解决：让模型自判够不够、要不要再查、何时停。技术：retrieve-or-not+multi-hop+self-critique+max_retrieval_steps 硬熔断+step 记账。何时：答案分布多源且下一步依赖上一步(多跳诊断)；单跳套循环是过度设计。
L5 Graph
解决：答案藏在实体多跳关系里时沿边推理；并厘清 RAG≠记忆。技术：三元组建图(networkx→Neo4j)+多跳 BFS/Cypher+社区摘要；记忆分层 DB/事件源/BM25/向量。何时：多跳/影响面/全局趋势用图；指代走会话记忆不走 RAG。

🔎 一条 query 进来的决策流

🎯 题眼：先判该不该查(结构化直查 DB 别硬 RAG) · 查了知道何时停(Agentic 的 max_retrieval_steps) · 答了能证明有据(grounding 校验做在模型外)。向量 RAG 找"像的"，Graph RAG 找"连着的"。
