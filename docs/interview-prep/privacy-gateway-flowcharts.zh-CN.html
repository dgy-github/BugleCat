🔐 Privacy Gateway 流程图详解 · 数据不出域

local-first 隐私网关：先本地、命中密钥硬 block、要外发先脱敏。 差异化亮点是把"数据不出域"落成工程——脱敏做在模型外、隐私等级 lattice 合并、复核失败有 guard。按真实代码逐块画流程，每图配面试要点。

① /ask·chat 主控② 隐私脱敏③ 风险路由④ 本地→复核⑤ 上下文⑥ 意图路由

① chat 主控制流（/ask 恒以 mode=review 进入）

面试要点
  • 先短路、后路由、再模型：一堆确定性短路（问候/空/危险执行/天气）不进模型；再走 action 路由；都不中才调本地模型。
  • mode 只有 local vs 非local 两个真实分支，pro 无独立代码路径；/ask 恒以 review 进入。
  • 出口统一 append：写 turn + 抽记忆 + 入后台压缩队列（见图⑤）。

② 隐私分级 + 脱敏（policies/privacy.py）

面试要点
  • 三级分级 public/internal/secret；SECRET 3 条、PII 4 条正则。
  • blocked 只由 SECRET 触发（PII 只替换不 block）——命中密钥则原文占位、绝不外发。
  • merge_privacy 是 lattice：多源取最高密级；脱敏在模型外做，不赌模型自觉。

③ 风险路由 review_requirement（7 分支优先级）

面试要点
  • 7 分支优先级：隐私 > 高危词(44) > 业务规则词(19) > 反直觉词(15) > 输入过长 > 回答过长 > low_risk。
  • 职责分离：review_requirement 只判"要不要复核"，不决定 mode；mode 由调用方传。
  • 大小写不敏感；隐私优先级最高——有敏感必复核。

④ 本地 → 线上复核链路（含 key 轮转 / 回退 / 失败 guard）

面试要点
  • 顺序：本地答 → 判是否需复核 → 脱敏 → 两条跳过快路径 → codex /responses(gpt-5.4) 复核。
  • 多 key 轮转 + deepseek 回退：可重试错误(401/429/5xx)轮换 key，主 key 全败降级 deepseek。
  • 失败 guard：复核挂了时若"需复核 & (策略非 allow_local 或已 blocked)" → guarded-fallback 拒绝本地当最终答，不是无脑放本地。

⑤ 上下文工程（前缀缓存 + 后台压缩 + 检索 + 记忆）

面试要点
  • prefix_cache 是整形不是压缩：把 system 合并成稳定前缀 + 剥易变元数据 → 前缀字节稳定 → 复用 llama.cpp KV cache（省首 token 计算）。
  • 后台异步压缩：append 入队，compaction_worker 线程批量压；secret 轮次只留占位。
  • 喂本地 vs 喂线上两套上下文：review_summary 全程脱敏且跳过 secret turn——上下文层再兜一道"不出域"。

⑥ 意图 / action 路由（两级：召回收窄 → LLM 定夺）

面试要点
  • 两级路由：ActionClassifier(本地 lexical+embedding 召回，收窄成 top5) → IntentRouter(小 LLM 定 kind/tool) → ActionRouter 执行。
  • 省 LLM 的两处：强召回(conf≥0.9)直连跳过 LLM；classifier 无候选时跳过 IntentRouter。
  • 工具路由隔离在主上下文之外——classifier 单独算，不污染 chat 上下文。
全局易错点（面试官爱挖）
  • mode 只有 local vs 非 local 两个真实分支，pro 无独立代码路径。
  • blocked 只由 3 条 SECRET 触发，PII 命中只脱敏不 block。
  • review_requirement 只决定"是否复核"，不决定 mode。
  • ActionPlanner 已实例化但当前链未调用；SessionStore(内存版)未被使用，实际是 ContextStore(sqlite)。
