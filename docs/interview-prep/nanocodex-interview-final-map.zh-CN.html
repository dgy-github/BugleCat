🧩 承重维度（点开看 承重 / L3 / 被追问）

🦀 ① 定位 + 为什么 Rust
自研·不为性能·编译期钉不变式

承重OpenAI Codex 用 Rust 从零重写，起源是我自己用 Coding Agent 的真实痛点（上下文/任务拆解/文件修改/执行反馈/测试闭环）——先理解问题→再抽象系统→再自己实现。full ownership。

L3单进程 current-thread Tokio，?Send + Rc<RefCell>（I/O 密集用单线程 join_all 做只读并发，非 OS 线程）；8 子系统绕 AgentLoop::run_turn。为什么 Rust：不为性能（agent 等模型/等工具，CPU 不是瓶颈）——为 ~199× 启动/2.4MB 单文件分发/类型系统编译期钉死循环不变式。

被追问"为什么不 Go"要的是编译期把 ?Send/借用/状态机不变式钉死的类型表达力 + 生态（async-trait/serde），Rust 更贴合把"能力袋"和循环状态建模。

🔄 ② Harness 主循环 run_turn
有界循环 + 双预算 + 历史合法性不变式

承重一回合 = for iteration in 0..max_model_calls 有界循环：组装上下文→调模型→有工具就执行→喂回→再循环，直到不带工具作答/error/cancel/触及预算。

L3max_model_calls = max_iterations.min(task_budget.max_model_calls.max(1))；双预算（model_calls/tool_calls，默认 150/300）；历史合法性不变式=backfill_unanswered_tool_calls 给悬空 tool_call 补占位 role:tool（否则下次请求 400）。

被追问"怎么防死循环"双预算 + 无进展检测 + max_model_calls 硬上限；五退出点（无工具/error/cancel/预算/max）。

🚪 ③ 权限双门 相对 codex 的再设计
两道正交纯函数门 + 能力剥夺

承重安全建在代码上不建在措辞上。一次写操作过两道正交的门：物理门判"能不能写"、越界门判"越界了怎么办"，再加一层人类提示。

L3SandboxPolicy.can_write（3 档模式 + 词法路径包含，纯函数零 I/O）⊥ Approver::classify（4 档 → AutoApprove/Ask/AutoDeny）。untrusted 三筛顺序：7 条危险正则先跑（rm -rf 即使被引导也拦）→ 29 条白名单（first_token）→ git 15 条写子命令。SessionGrants 精确匹配（ls -la≠ls -l），session 级即丢。PolicyExecutor 只做容器（Job Object+timeout），不碰审批。能力剥夺：read-only 下 can_write 恒 false、plan mode 拒所有写。

被追问"danger-full-access 全放吗"否，只清零 escalation bit 不改 approval policy；untrusted+danger 下未知命令仍 Ask。

🗜 ④ 上下文压缩（非破坏）
发送时视图·原始历史不动·两趟

承重for_model_edited 构建发送时视图，self.messages 原始历史不动（非破坏）：压旧 tool 结果 → user 边界丢最旧前缀。

L3切点绝不落在 tool_result（否则历史以孤立 tool 开头→400）；非破坏才敢激进压（resume/回放/换模型都吃原始）。

被追问"为什么非破坏"压缩是有损猜测，保留原始是唯一能兜底的地基。

🎭 ⑤ 编排 best-of-N
靠结构不靠更聪明模型·无消息总线

承重高复杂度任务靠结构：classify→plan→N 个 worker 并行→verify 选 winner→回灌重试。

L3父子无消息总线，三通道：prompt 下发 + 文件隔离-提升（copy_tree 私有 scratch，winner 才 promote）+ PASS/FAIL/BEST 裁决回灌。classify/plan/verify 走 reason() = 空 ToolRegistry（代码级拿不到工具）；用尽重试仍 promote best 标 [unverified]。

被追问"子 agent 怎么通讯"不对话——文本是下行通道，磁盘才是代码的真 IPC，裁决文本是回路。

🧠 ⑥ 记忆
线索不是事实

承重项目记忆是"线索不是事实"。

L3recall 注入标 RECALL_HEADER（"线索而非事实"）；remember 仅 CONFIRMED + 精确去重；consolidate(0.85) 启动即幂等去重。

被追问"为什么当线索"记忆会过期（记的文件/flag 可能已不存在）——注入当线索让模型去验证，不当既定事实直接落地。

🧬 ⑦ ncx-forge 离线演化 相对 codex 独有
只演化文字不动行为·训练接缝即安全边界

承重让 agent 离线自动优化自己，但只演化文字、不动行为。

L3genome = system_prompt + 工具描述（纯文本）；NCX_GENOME 是训练↔运行唯一接缝；可证明 no-op（空/错→字节级回退默认）；执行始终过沙箱→被不可信失败轨迹喂养的 teacher 也注入不了新能力（训练接缝即安全边界）；sentinel 门无法证明注入生效前拒绝训练。

被追问"离线优化会不会引入风险"能演化的只有文字，执行永过沙箱——离线训练改不动安全边界。

🕒 ⑧ 定时器设计 🆕 并入
难点不是计时·是无人时 Ask 怎么办

承重给单文件 CLI agent 加调度。难点不是计时（那是 OS 的事），是"没人在场时 Decision::Ask 怎么办"。

L3委托 OS 调度器（Task Scheduler/cron/launchd）spawn 无头单发 ncx [PROMPT]（复用既有单发路径，~5.5ms 冷启动让 per-fire 进程免费，不自带 daemon）；声明式 ~/.nanocodex/schedules.toml（沿用 config.toml/mcp.toml 约定）；无人值守解析器 Ask→Deny fail-closed（classify() 一行不改，复用双层门零新权限，是"能力剥夺"范式延伸）；per-id 锁文件防重叠（同排产订单锁，带 TTL）。

被追问"无人时 Ask 怎么办 / 算不算新攻击面"fail-closed Deny——新增决策是收紧非放宽；写操作要在配置里显式预授权一个不产生 Ask 的策略组合（授权前移到写配置那刻）。呼应 forge"训练接缝即安全边界"同一信条。

🧭 ⑨ 驾驭工程（元）+ 哲学
模型第一杠杆·harness 第二杠杆

承重核心信念——模型是第一杠杆，harness 是第二杠杆。编排靠结构不靠更聪明的模型，forge 只演化文字，沙箱托底。

L3四信条同排产：LLM 原始输出不直接落地 / 安全建在代码不建在措辞 / 有确定性判据就别用 LLM judge / 数据不出域。

与排产对称同一套驾驭工程，nanocodex 长成"沙箱+best-of-N+离线演化"，排产长成"确定性 workflow+四段治理+评测飞轮"；骨架同，承重随业务。

🔥 硬追问补充（跨维度·被钻时用）

和 codex 什么关系，是不是抄的？
能搬则搬，承重处自己再设计

能原样搬的逐字搬（apply_patch 工具描述 / @path / tool_calls 形态 / 沙箱三模式 / 审批四档）——这是工程诚实，不重造轮子。但权限双层正交纯函数 + 代码级能力剥夺 + ncx-forge 训练接缝即安全边界，是我的再设计。能搬则搬，该做工程判断处自己重设计——这才是 full ownership。

?Send+Rc<RefCell> 为什么不用多线程？
I/O 密集，瓶颈不是 CPU

agent 是 I/O 密集（等模型/等工具），CPU 不是瓶颈；单线程 join_all 做只读并发够用，还免掉 Send 约束的复杂度。要的是编译期把循环状态机不变式钉死，而不是压榨多核。

工具可见上限 9 为什么？
工具太多模型选择退化

暴露的工具越多，模型选择越容易退化/误选；卡在 9 控制暴露面，让每次决策的候选集小而清晰。呼应"harness 是第二杠杆"——约束比堆能力更值钱。

genome 演化了怎么知道没变坏？
sentinel 门 + 可证明 no-op（诚实缺口）

NCX_GENOME 注入前过 sentinel 门（证明不了注入生效就拒绝训练）+ 可证明 no-op 回退（空/错→字节级回默认）。诚实缺口：目前没有行为回归 eval 集验"文字变了但行为没退化"——这是优化项（见优化卡）。

怎么调试线上跑偏？
NCX_TRACE env 打点

置 NCX_TRACE 打开链路打点，看组装/调模型/工具/裁决每步的输入输出定位。优化方向：升结构化 span/OTel 父子树（呼应排产可观测优化），现在是扁平打点。

🚀 优化方向（被问"怎么优化/下一步"·现状→优化）

答法：现状能用 + 有 X 局限 + 方向 Y + 当前不做因为 Z。

🧬 ncx-forge（最大缺口）
只 sentinel 门 → 加行为回归 eval

现状sentinel 门 + 可证明 no-op 回退，只保证"能安全回退"。

优化加行为回归 eval 集（文字变了跑一批任务比通过率/工具序列，退化则拒绝晋级）+ A/B genome 对比 + held-out 防对训练轨迹过拟合。这是 forge 从"安全"到"可信有效"的关键一步。

🎭 编排 best-of-N
纯文件+裁决文本 → 回灌学习+多裁判

现状无消息总线，靠文件隔离+PASS/FAIL/BEST 裁决文本；worker 间不学习。

优化失败 worker 的轨迹回灌 forge 学习；verify 从单裁判升多裁判对抗投票（呼应 workflow adversarial verify）；跨 worker 结构化 artifact 索引减重复探索。

🗜 上下文压缩
两趟启发式 → 学习式重要性评分

现状两趟启发式（压旧 tool 结果 + 丢最旧前缀），非破坏。

优化加学习式重要性评分决定丢谁 + 工具结果摘要模型（借鉴 pi 的 compact 摘要，而非直接截断）；仍守非破坏原始历史。

🧠 记忆
精确去重 → 向量化语义去重+分层

现状精确字符串去重 + consolidate(0.85)。

优化向量化语义去重（近义线索合并）+ 分层记忆（会话/长期/项目）+ 过期线索的时效衰减。

🚪 权限
静态29白名单 → 项目级可学习信任

现状29 条静态白名单 + 7 危险正则，全代码内置。

优化项目级可学习信任策略（某仓库常用且历史安全的命令可提信任），但判定仍在代码不给模型、危险正则永远兜底——扩的是白名单来源，不是把决策权交出去。

👁 可观测
NCX_TRACE 扁平 → 结构化 OTel 树

现状NCX_TRACE 环境变量开扁平打点。

优化升结构化 span / OTel 父子树（嵌套工具/子 agent 可见）+ 每回合 token/延迟/退出原因指标（呼应排产可观测优化，两项目同一方向）。

🕒 定时器
MVP OS单后端 → cron/launchd+补跑

现状设计阶段；MVP=Windows Task Scheduler 单后端 + 无人值守解析器 + 锁。

优化补 cron/launchd 后端 + on_missed 补跑 + 结果通知（文件/webhook）+ 预授权写任务的显式校验 + Ask→Deny 解析器的属性测试。详见设计文档分阶段计划。

🔄 主循环诊断
无进展检测较粗 → 降级重规划信号

现状双预算 + 无进展检测 + 硬上限。

优化更细的循环诊断（区分"卡住重试" vs "该重规划"），触发自动降级/重规划信号而非闷头耗预算——呼应排产 verify 输出"重试 vs 重规划"的同思路。

🧾 一句话总纲（背这句）

nanocodex 是我从用 Codex/Claude Code 的真实痛点出发、用 Rust 从零重写的编码 agent 工程底座。选 Rust 不为性能而为 ~199× 启动 + 单文件分发 + 编译期钉死循环不变式。相对 codex 最大的再设计=权限双层正交纯函数 + 代码级能力剥夺 + 训练接缝即安全边界；连定时器都用同一信条（Ask→Deny fail-closed、复用双层门零新权限）。贯穿哲学：模型是第一杠杆、harness 是第二杠杆，安全建在代码不建在措辞。
