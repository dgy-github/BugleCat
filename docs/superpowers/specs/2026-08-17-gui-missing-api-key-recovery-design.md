# GUI 缺少 API Key 时的恢复设计

## 目标

首次启动 GUI 且尚未配置模型凭据时，应当进入可恢复的配置状态，绝不能退化成无关的
`agent thread is not running`（agent 线程未运行）错误。

## 范围

- 初始 Agent 创建失败时，GUI 命令接收通道仍然保持可用。
- 前端事件监听器就绪后，能收到实际的初始化错误。
- 缺少 API Key 时，界面展示明确的“需要配置”提示。
- 用户在界面设置中保存 API 配置后，自动重载 Agent，无需重启桌面应用。
- 配置有效时的既有行为与会话重载行为保持不变。

## 方案

Bridge 工作线程在 `build_agent` 失败后继续保留命令循环，只是把 Agent 标记为不可用，
而不是直接退出。依赖运行中 Agent 的命令会返回或发送已保存的初始化错误；`Reload`
命令仍然可用，用于配置保存后的再次初始化。这样命令通道不会断开，后续配置也可以恢复。

前端记录“已就绪 / 初始化失败”状态。当错误说明没有 API Key 时，显示配置提示并引导
用户打开已有的设置界面。在收到成功的 `ready` 事件之前，权限模式选择器不向运行时发送
命令，避免前端乐观状态与后端状态不一致。

设置保存的既有重载路径会再次尝试创建 Agent；成功后发送 `ready`，前端自动移除配置提示
并重新启用运行时控件。

## 错误处理

- 配置格式错误仍显示具体校验错误。
- 缺少 API Key 是“需要配置”的状态，不是工作线程崩溃。
- 就绪前收到命令时，返回准确的“Agent 尚未配置”错误，绝不再返回“线程未运行”。
- 继续使用已有的 `ready`、`error` 和重载事件；不向前端传递任何密钥内容。

## 测试

- 后端：初始 `build_agent` 失败后，工作线程仍可接收命令；`Reload` 可以恢复至 `ready`。
- 前端：尚未 `ready` 时，选择权限模式不会调用 `set_permission_mode`。
- 回归：缺少 API Key 的启动路径不再显示“线程未运行”。

## 非目标

- 不新增凭据保存机制或完整的新手引导页。
- 不把 Codex 桌面版登录态自动当作 API Key 使用。
- Agent 就绪后的 provider、沙箱和权限模式语义不变。
