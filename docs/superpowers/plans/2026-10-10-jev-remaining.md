## 本期目标

让 Agent 的四类声明可核验：是否实际执行、测试是否通过、结论是否超出验证范围、验证是否已过期。证明确定性规则带来的收益，再衡量 Jev 的额外收益。复杂根因、架构正确性、任意语义事实继续按证据表达不确定，不要求全量自动认证。

“旁路可用”“规则可拦截”“Jev 可拦截”是三个独立交付状态。源码完成、测试通过或 API 返回成功都不能替代效果认证。

主要文件：`verification/evidence.rs`、`types.rs`、`session.rs`、`context_store.rs`、`context_trace.rs`、`instruction_state.rs`，必要时工具执行结果所有者。先读已有类型和调用方，不另建第二套事件存储或指令系统。

- [x] 通过 tool_call_id + 事件序列 + 工作区关联命令、结果、前后快照。核验范围是实际工具工作目录/目标，不只是项目根目录；对跨目录、显式 workdir、重命名、符号链接和失败读取保留明确状态。缺实际替代工具身份的 recovery 结果保守 Unknown。
- [x] 证据选择先绑定同一验证目标，再判断时间/覆盖：失败后修复且重跑成功，旧失败仍保留审计但不永久否决新声明；不同文件或不同测试范围的成功不能抵消失败。真实开发对照暴露旧失败缺 snapshot 的误拦，已追加回归修复；未重刷收费结果。
- [x] 用结构化引用或宿主候选证据 ID 关联声明，不再要求面向用户的回答必须包含完整命令；模型提出的引用只作候选，仍由宿主核验。
- [x] 复用 InstructionLedger 表达 Active/Superseded/Revoked/Conflicted，保留来源、时间与作用域；先可靠处理明确撤销和替换，模糊归并保留冲突。仅支持显式前缀与精确主体；复杂归并不猜授权，工具/引用不能撤销人类限制。
- [x] 从原始用户事件与安全来源重建有效要求，明确摘要只提供线索；多段文本、附件元数据及用户改口有覆盖测试。附件内容和不完整旧来源仍 Unknown；不能仅用已压缩的 messages 声称完整历史覆盖。
- [x] 对无可靠来源、证据裁剪、需求冲突分别输出原因码和覆盖信息。

验收场景：A 工作区结果用于 B 必须拒绝；测试后改文件失效；同一目标修复重跑可恢复；局部通过不能抵消另一范围失败；用户“不要修改”后明确允许修改可正确更新；引用文本/工具输出不能撤销用户限制；恢复会话仍保持来源与范围。

交付：契约增量、事件写入/读取兼容、上述 Rust 回归与可复核的匿名证据包示例。不能靠降低检查条件消除 Unknown。
