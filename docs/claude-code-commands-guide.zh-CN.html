先建立一个总模型

Claude Code 里的 / 菜单不是单一类型。它更像一个路由器，把“内置操作”“Markdown 指令模板”“Skill 工作流”“插件提供的能力”和“MCP prompt”放在同一个入口里。

01

内置命令

由 Claude Code 程序本身实现，常用于清空上下文、导出会话、修改配置、登录、查看状态等。原理是直接调用 CLI 的内部能力，不只是给模型发一句提示词。

02

Skill

一个 SKILL.md 包。前置元数据告诉 Claude 何时触发，正文给工作方法，必要时再读取 references/scripts/assets。原理是“渐进加载”，节省上下文。

03

插件命令

插件可以提供 commands、skills、agents、hooks、MCP server。命令通常是 Markdown 文件加 frontmatter，通过允许工具、参数提示、模型偏好来定义工作流。

04

自定义命令

项目或用户目录里的 .claude/commands/*.md 会变成 slash command。原理很朴素：把文件内容展开成 Claude 要执行的专用任务说明。

/remote-control 远程控制 让当前终端会话可以从 claude.ai 远程控制。 建立本地 session 与网页端的控制通道。 想在网页端接管或监控本地 Claude Code 会话。 需要账号、网络和远程控制权限。
/review 官方内置/Skill 审查 GitHub Pull Request。 读取 PR diff 和上下文，使用 review 引擎生成问题和建议。 看远端 PR；本地当前 diff 更适合 /code-review。 需要 GitHub/gh 权限。
/run Bundled Skill 启动并驾驶当前项目应用，真实观察运行效果。 识别项目启动方式，运行 app，再通过终端/浏览器/截图验证。 前端、CLI、服务端功能改完后想看真实行为。 需要项目依赖和运行环境可用。
/run-skill-generator Bundled Skill 为项目生成指导 /run 和 /verify 的项目级 skill。 把“如何构建、启动、访问、验证这个项目”沉淀成可复用流程。 项目启动步骤复杂，Claude 每次都要重新摸索时。 可能写入项目 skill 文件，需要 review。
/security-review 内置/示例工作流 对当前分支或待提交变更做安全审查，寻找注入、鉴权、越权、密钥泄露、不安全数据流等问题。 把 Claude 的评审目标限定为安全威胁，并通常围绕 git diff、文件读取、grep 等证据展开。它不是普通代码美化，而是“威胁建模 + 漏洞扫描”的提示词框架。 登录、支付、权限、上传、外部输入、数据导出、发布前检查。 不能替代人工安全测试或 SAST/DAST；高风险系统仍要复核。
/session-compact 本机自定义 Skill 把很长的会话压缩成短 handoff：目标、已确认事实、已做决策、未决问题、下一步。 读取本机 SKILL.md 的固定模板，只保留“下一步仍需要”的工作记忆，丢掉旧分支、日志噪声、重复解释。 会话太长、模型开始忘约束、准备换子任务、想把上下文交给新会话。 它压缩的是对话上下文，不会压缩仓库文件；关键证据最好仍保留在文件里。
/setup-cowork Anthropic Skill 引导配置 Cowork/协作环境，推荐或安装角色匹配的插件、连接工具，并试跑一个 skill。 把“环境初始化”拆成一套可复用清单：检查使用场景、选择插件/工具、写入配置、验证是否可用。 新机器、新项目、团队成员第一次接入 Claude Code/Cowork。 可能改 settings 或安装插件；执行前看它要改哪些文件。
/simplify Bundled command 审查当前改动，寻找可复用、可简化、可提升效率或可降低抽象高度的地方，并可直接应用修正。 它把任务目标设成“保持行为不变的重构”，重点是代码清晰度和维护性，而不是主动找功能 bug。 功能已经跑通，但代码显得绕、重复、过度设计，准备提交前做一轮打磨。 如果你想找 bug，用 /code-review 或 /review 更合适。
/skill-creator 官方插件 Skill 创建、修改、评估 Claude Skill，包括写 SKILL.md、设计触发描述、做测试 prompts、迭代优化。 基于 Skill 的三层结构：元数据常驻、正文按需加载、references/scripts/assets 渐进读取。再通过 eval loop 比较有 skill 与无 skill 的效果。 你想把一套常用流程沉淀成可复用能力，比如“生成中文投标书”“读取固定格式表格”。 Skill 描述写得太宽会误触发，写得太窄会不触发；需要用真实任务测试。
/team-onboarding 版本内置/条件显示 根据本地 Claude Code 使用情况生成队友上手指南，比如常用命令、项目习惯、推荐工作流。 从本地使用记录、配置、插件/技能信息中抽取“团队协作知识”，转成新同事可读的 ramp-up guide。 新人入组、交接项目、想把自己的 Claude Code 工作方法整理给同事。 可能涉及本地使用痕迹；分享前检查是否包含私密路径、账号、项目名。
/update-config 配置 Skill 帮助修改 Claude Code 的 settings：权限、环境变量、hooks、自动化行为、settings.local.json 等。 把“偏好记忆”和“真正可执行配置”分开：自动化、权限、hook 必须落到 settings JSON，不能只靠模型记住。 你说“以后每次 X 都 Y”“允许 npm test”“添加环境变量”“配置 hook”的时候。 它可能改变后续所有会话行为；建议改完看 diff。
/usage-credits 账号/用量命令 查看当前账号、套餐、额度或用量相关信息。 通过 Claude Code 的登录状态和服务端账号信息展示额度，不依赖当前代码仓库。 想确认剩余额度、是否接近限制、为什么模型/远程功能不可用。 不同订阅、组织、版本显示不同；它通常不修改项目文件。
/verify 验证 Skill 验证一个代码改动是否真的可用：运行应用、执行测试、观察 UI 或命令输出。 采用“不要只相信实现描述”的独立验证闭环：用真实运行结果、测试计数、截图或日志来确认。 修完 bug、合 PR 前、用户说“确认一下是不是真的好了”。 会运行项目命令，可能需要浏览器/服务进程/测试环境。
/xlsx 文档处理 Skill 读取、创建、编辑 Excel 工作簿：表格、公式、样式、多个 sheet、导入导出。 借助专门的 spreadsheet 处理流程和库来保留 workbook 结构，比把表格当纯文本更可靠。 财务表、运营表、商品 SKU 表、需要生成或批量修改 .xlsx 文件。 注意隐私和公式正确性；复杂表建议改完抽样打开核对。
/clear 官方内置 清空当前对话历史，让后续回复不再背着旧上下文。 重置会话上下文窗口，减少 token 占用和旧信息干扰。它改变的是 Claude 的“工作记忆”，不是 git、文件或终端状态。 任务结束、上下文变脏、旧目标已经不相关、想降低 token 成本。 清掉后 Claude 可能忘记你刚才的约束；重要信息先写进文件或 handoff。
/export 官方内置 导出当前会话，便于分享、归档、交接或复盘。 把 transcript/session 信息序列化为可保存文件。它是“把过程拿出来”，不是运行代码。 需要把一次排障过程交给别人、保存证据、整理项目复盘。 导出前检查是否包含密钥、账号、商业信息或本地路径。

小结：看到 / 菜单时，先问一个问题：这个指令是“改变 Claude Code 状态”，还是“给 Claude 一套任务模板”？前者通常是内置命令，后者通常是 skill/插件/自定义命令。

自己写一个命令时，Claude 真正读到什么

自定义 slash command 的核心是一个 Markdown 文件。它不是 shell alias，而是“给 Claude 的任务说明 + 可选执行约束”。

一个好命令像“任务卡”，不是“万能咒语”。

名字要短，职责要单一，允许工具要收紧，参数要明确，输出格式要稳定。这样 Claude 执行时更少漂移。

---
description: Review code for security vulnerabilities
argument-hint: [optional target]
allowed-tools: Read, Grep, Bash(git diff:*)
model: sonnet
---

Perform a security review for $ARGUMENTS.

Focus on:
- authentication and authorization
- injection risks
- secret leakage
- unsafe file/network operations

Return findings with file path, line, severity, and recommended fix.

frontmatter 控制“怎么运行”

description显示在菜单里，也帮助 Claude 判断何时使用。
argument-hint提示用户要传什么参数。
allowed-tools限制这个命令能用哪些工具，降低误操作风险。
model/effort为复杂度选择模型或推理力度。

正文控制“做什么”

$ARGUMENTS把用户在命令后的所有参数插入任务。
$1读取第一个参数，适合固定参数位置。
@file把文件内容作为上下文引用。
!`cmd`先执行命令，把输出注入上下文；要谨慎授权。
