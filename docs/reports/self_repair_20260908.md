# BugleCat 六类自我修复测试报告

运行标识：`20260908_003124`（UTC）。模型：`deepseek-v4-pro`。

## 一句话结论

在 6 道真实源码故障注入题中，首轮补丁通过 5 道；最多一次反馈后累计通过 6 道。首轮同时满足验收通过、正常完成且未超时的有 5 道。无效基线/注入 0 道；无法可靠验收的基础设施异常 0 道。

最终通过且正常结束的共有 6 道；这与只留下可用补丁、进程却超时或失败的情况分开统计。

这里的“通过”由独立测试判定，不采用模型自述，也不把进程退出 0 当作修复正确。每类只运行一道、一次初始尝试，且指定目标文件、提供功能约束和可见测试；这不是无提示的全仓库诊断，样本不足以代表稳定成功率或所有代码修复能力。

## 怎么测：先证明题目真的坏了

1. 对健康源码运行真实回归测试，必须通过。
   还会模拟 Agent 的精简 shell 环境，验证冻结测试入口能运行；缺失工具链时不进入模型修复。
2. 在独立工作副本注入可复现缺陷，测试必须出现断言失败；编译环境故障不算有效题目。
3. 只在故障注入后创建单提交 Git 历史，不导出健康历史、历史答案或本套验收器。
4. BugleCat 编辑真实所属文件；外部检查改动范围、既有测试完整性，再独立运行验收。
5. 首轮失败可收到一次测试反例反馈，不能由外部助手代写候选修复。

这是合作式开发自测，不是防作弊竞赛沙箱：workspace-write 不阻止读取宿主其他目录，共享编译缓存也不是隔离边界。未导出答案不等于操作系统强制禁止访问答案。Rust 验收使用可见但冻结的真实回归测试；Python 分类题另有外部验收。

## 指标怎么读

- 首轮通过：不给反例反馈时，第一次生成的补丁满足独立验收。
- 反馈后通过：允许同一工作副本再修一次，不能与独立首轮成功率混算。
- 正常完成：验收通过之外，CLI 退出 0 且没有触发外层超时；与补丁正确性分别统计。
- 无效题：健康基线失败、注入后未复现测试失败或环境无法运行，不能冒充模型修复失败。
- 基础设施异常：验收启动失败、验收超时等单列，不能当作已确认的功能错误。
- 本批 CLI 实际启动 7 次，Agent 累计 659.65 秒（约 11.0 分钟）；独立验收/编译时间另计，不混入 Agent 时长。

上列验收耗时属于原运行；最终清理缓存后重新编译复验的耗时另记于 independent_recheck.json。

每次 Agent 总预算 600 秒，外层回收 630 秒，最多 30 次模型调用/80 次工具调用；HTTP 调用沿用运行时的有限重试策略。独立验收每次最多 600 秒。没有定时任务。

## 本次失败与改进，怎么理解

唯一需要反馈的是补丁定位题。首轮没有生成补丁，CLI 退出 1；Provider 记录 `stream_error`，HTTP 状态虽然是 200，但对应等待约 120 秒。这说明收到 HTTP 响应不等于流式生成完整成功，不能据此判断模型已经完成修复。一次反馈后，BugleCat 自己补回上下文定位逻辑，19 项该题回归全部通过。

评测过程中也暴露并修正了两项测试基础设施问题：Agent 精简 shell 环境导致 Windows 编译器发现失败，以及共享 Cargo 目录复用其他副本的旧构建产物。前者通过冻结测试入口与环境预检解决；后者通过仅清理四个可变包的 dev 产物并重新编译解决。中止的早期试运行单独保存在 [PILOT.md](../../evals/self_repair/results/20260908_001556/PILOT.md)，不计入上述正式成绩。

最终独立验收合计 **40/40** 检查通过。这是六道题内部的检查项数量，不是 40 道独立修复任务，也不应据此宣称普遍成功率为 100%。
