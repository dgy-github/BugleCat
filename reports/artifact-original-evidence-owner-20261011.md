# Original artifact evidence owners — implementation audit

Date: 2026-10-11. Root changes and audits below made **0 HTTP / 0 new paid calls**. Paid main collection is a separate, source-preregistered operation; this report does not certify its statistical effect.

## Independent provenance

Formal intake rejoins original source manifests, prepared seals, global SQLite starts and finishes, receipt bytes, actual compiled main source/executable, raw responses and independent Oracle receipts. Every actual start in a cohort remains represented, including failed/pending/unknown records. Supported or unsupported labels cannot be rewritten as unknown to remove a denominator. A merely prepared, unstarted old-cohort case can later have a fresh start in another registered resource profile; that newer start is not retroactively an old-cohort request. Nonoptional formal proof still rejects a foreign cohort.

Formal calibration re-derives the original registration from source and independent labels, independently verifies every actual Jev transport observation, computes the frozen grid and confidence gates, and rechecks the original bytes. Runner attestation uses explicit old / high / holdout entrypoint dispatch and all compiled helper paths, including engine, main validator, provider and holdout owner sources. It does not reinterpret an old source hash as the new profile.

The once-only holdout owner verifies the original calibration rather than a caller's status string, excludes the entire calibration allocation, locks the threshold and binds opening/label/evaluation markers to the shared original ledger. Failure after a consumption marker does not permit another output. `revalidate_evaluation` reconstructs the exact fixed result from original evidence, including the marker's observations and output paths. Numeric success can certify only the separate frozen MBPP artifact benchmark; native claim certification, overall agent decision benefit and production remain false.

## Measured verification performance

An actual zero-fee read-only timing initially reverified seven original high-profile rows in **6.283 seconds** (0.898 seconds/row). Each call reconstructed the complete official expanded benchmark catalog, creating a concrete risk that bounded pre-transport proof would time out before sending.

`source_bindings.verified_sources` now scopes immutable manifest/catalog proof reuse to one verification operation. It preserves the original source/group/interface checks. A cache hit hashes every original bound input, returns copied task/index data, and verifies every distinct manifest's cases. It does not cache ledger contents, reservations, labels, candidate/Oracle receipts or probabilities, and never persists across operations. Nested owner calls share the same bounded read-only transaction; exit or exception clears it. Source cache changes are outside the original source cohort's bound Oracle/registry/cohort/expansion inputs and do not modify the actual source, prompts, groups or provider request builder.

With the transaction enabled, **46 actual original eligible rows across six completed high batches reverified in 4.726 seconds** (0.103 seconds/row). These are timing measurements of existing evidence, not additional benchmark samples. Full qualified calibration and holdout timing remains unmeasured until genuine independent label and probability prerequisites exist.

The new holdout compiled guard binds the source owner through `source_binding_owner_source_sha256` in addition to its other owner/source fields; the root verifies the same exact path. The guard is read-only and has no inherited provider credentials. Its audit budget is separate from the frozen 120-second main-provider request timeout.
